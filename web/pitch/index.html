The problem

AI agents are powerful.
And completely invisible.

They live trapped in a chat window or a scrolling terminal. You can't see a team working, can't tell who's doing what, and close the tab and the "office" is gone. Multi-agent work feels like managing ghosts you can't point at.

no presence

no place

no control

Trust, blindly

no rhythm

The living world

A place, not a dashboard.

An HD-2D office rendered behind your desktop icons: 3D rooms, pixel-art people lit by the scene, reflective floors, tilt-shift focus, film grain — and countryside outside the glass.

Nine swappable rooms on a 3×3 jigsaw grid — Executive, Operations, Lobby, Cafeteria, Server, Meeting, Recreation, two Dormitories. Click two rooms to swap; furniture, seats, navigation and the pets follow.
Real day and night — sun, sky, ambient light and reflections follow your machine's clock; a roofline clock and a manual atmosphere picker for golden-hour shots.
The Ghost Deck — a floating glass platform with 12 desks where an agent's parallel clones work, then glide home and dissolve back into their owner.
Nameplates and FX — MMO-style plates with a live state pill; ✅ ❌ ❗ 👍 🎵 flipbooks over heads; equippable elemental auras; a gold crown for you, a lead star for the Director.
Ambient life — agents nap in a bunk, watch the rec-room TV, kick a football, drift into groups to chat; a cat, dogs, bird flocks, fireflies, and the odd server-room fire 💥 someone runs to put out.
It never disappears — a world supervisor re-embeds the wallpaper within ~2 s whenever Windows tears the desktop down (resolution change, Explorer restart, a fullscreen game).
Your own furniture — the Office Editor places walls, decor and imported .glb / .gltf / .fbx models and images into the world, atmosphere intact.
Mission Control — an in-world board with one card per running task, and a lobby totem that shows daemon connectivity: truth, not decoration.
Chain of command

You are the CEO.
He is the Director.

Talk to one manager. Order the CEO and the Director walks over, takes the order, replies with a plan, and dispatches real sessions to the team with DELEGATE: lines — each hand-off acted out on the floor, each result reported back up the chain.

your order→Director plans→DELEGATE: agent @ project :: job→results report back→follow-ups→he walks the summary to your desk
👻 sub-agents

Self-splitting ghosts

Any session may end a reply with SUB: lines when the request parallelizes — the daemon spawns clone sessions, each in its own 👻 thread, then resumes the parent for a synthesis. Ghost isolation gives each clone a private git worktree, so two ghosts editing the same file both succeed and their work comes back as branches.

🗣 meetings

Real discussions

Pick 2–4 agents and a topic — round-robin turns over a shared transcript, minutes on the in-world whiteboard, and agents that research with tools mid-meeting to back an idea up.

📁 projects

Real folders, resumable

Register any folder; the Director creates new ones with a PROJECT: line and routes work into them. The assignee's session lives inside the directory and you can resume it yourself — one window per project, one occupant at a time.

💡 proposals

They pitch you

Idle agents drift together for small talk that can turn into a written project proposal — real websites, apps, plugins. You approve or reject each one with your reasons, which is how the team learns what you want next.

Spatialized security

Permission has a place too.

When an agent needs a tool you haven't granted, its character walks to the Security Center and waits — amber light, ❗ over its head, the exact command on your screen. The hook really does long-poll the daemon until you decide.

Allow · ✓✓ Forever · Deny — a denial makes the agent visibly re-plan; forever adds the tool to its profile so it never asks again.
Granted tools run silently — and the agent doesn't even leave its desk; a short grace confirms a trip is actually needed.
A project's own hooks are a separate yes — a folder that ships .claude/settings.json hooks raises a card with the literal commands and parks the work until you answer; editing the hooks asks again.
Run it somewhere else — point the office, or one agent, at a throwaway Docker container or a machine over SSH. The container sees the office read-only and the working directory, nothing else; keys travel by name, never by value.
Refused, not downgraded — a backend that can't be built correctly (say, the permission broker can't be installed) is refused outright, because a run that loses its broker works fine with nobody watching.
Everything local — the daemon binds 127.0.0.1, API keys live in a masked vault and are injected per run; your code never leaves the machine unless you point a brain at a cloud.
per agent: provider, model, and a live context meter in the chat

Memory & learning

It gets better the longer you keep it.

Nothing starts from zero. The office remembers what it did, distills it into notes and skills, retrieves only what's relevant, and — carefully — corrects its own mistakes.

🧠 memory

Three tiers, written for you

A shared OFFICE.md, a memory file per agent and one per project — distilled automatically after real work. A BM25 index (zero deps, works in Thai) injects only the memories relevant to the task, never a blind dump.

🔎 semantic recall

Words and meaning

Point the office at any OpenAI-shaped embeddings endpoint — a local Ollama costs nothing and keeps memory on the machine — and word and vector rankings are fused, so "why did the wallpaper vanish" finds the note about WorkerW teardown.

📚 auto-learned skills

Hermes-style learning

After a multi-tool task, a reflection pass decides whether the work distills into a reusable skill; if so it's saved, assigned and announced with a golden burst in the world.

🔧 self-correcting

It fixes what it wrote

The same reflection can correct a skill it already wrote, and runs after failures — the strongest evidence a skill is wrong. Never a built-in, never one you edited by hand; the previous version is kept.

🧪 skill regression

Tests before it changes

A skill can carry test cases. A proposed correction runs every case first, and one that breaks a case is refused — visibly, with a notification saying why. Self-improvement that cannot quietly get worse.

Autonomy

Work that doesn't wait for you.

The gap between "an assistant" and "a team" is what happens when you're not typing. The office has a rhythm of its own — and brakes you set once.

🤖 AUTO

Keep-going mode

An agent that hits a fork decides within its remit and opens its own next turn — up to 8 rounds, each announced in chat. It still stops dead for a credential it can't get or anything irreversible, and that block is pushed to your phone.

⏰ standing jobs

Works on a schedule

"Every morning at 8, brief me." Run now, at a datetime, daily, or every N minutes. A fired job is a real order, not a reminder — the Director dispatches it to the team and the results come back to him.

💓 heartbeat

The Director makes rounds

Every 15 / 30 / 60 minutes he reviews the calendar, the standing jobs and the note board — and pings you only when something deserves it. "OK" stays silent.

📥 one inbox

Asks you once, where you are

Tool permissions, project trust, pitches, a blocked agent, jobs created switched off, a workflow's approval, anything a plugin asks — one queue, with history and a note box. Answer in the sidebar, the terminal, or with a tap on Telegram. Answering a blocked agent resumes its work.

🔔 notifications

Rules, not noise

Per kind, route to the sidebar list, a pop-up, your channels, a sound — always, outside quiet hours, or only when you're away from the keyboard.

💸 budgets

Caps in money

A dollar cap per day for the office and per agent, per project for its lifetime. A warning at 80 %, new turns refused at 100 % (running work finishes), estimates labelled ≈, and a 🌅 morning digest of what yesterday cost and what's waiting.

♻️ A watchdog respawns the daemon if it ever dies · a run that ends abnormally writes why into the history · 🌱 Eco mode cuts idle token burn without slowing your direct orders.
Workflow engine

Draw it. Then it runs itself.

Plan work as plain-language nodes on a drag-drop canvas; the Director tells you which skills, tools and agents it needs. Press Run and the office executes the graph — every node on its own, in parallel where the arrows allow, joins that wait, decisions that open one branch.

⚡ trigger→🤖 action→🌐 fetch→🔀 decision→✋ approval→🔔 notify→⏳ delay→📤 output
Starts without you — on a schedule, from a webhook, on an office event, when a file lands, from a keyword you type on your phone — or on an RSS item, a kind a plugin added.
Survives a restart — every run is a persisted record: delays re-arm, approvals stay in your inbox, a mid-flight step is marked failed rather than pretended.
Data flows down the arrows — {{prev}}, {{trigger.data.x}}, {{n3.output}}; a decision is an expression or a question the Director answers.
Every action is a real agent turn — with that agent's persona, memory, tools and brain, and every outward step behind an approval.
Plugins extend it — a plugin can add its own trigger kind and its own node type (the Content Pipeline adds rss and fetch-article).
Also a skill — build-workflow lets an agent draft a workflow for you from a sentence.
